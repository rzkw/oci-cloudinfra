## Tasks 3 & 4 completed (this PR)

Phase A, Task 3 — remove bastion + service gateway from `terraform/vcn`
- `terraform/vcn/main.tf`:
  - Removed `data "oci_core_services" "all_mel"` (only fed the service gateway).
  - Removed `oci_core_service_gateway.internal` (display name
    `servicegateway20260720114218`).
  - Removed the `SERVICE_CIDR_BLOCK` route rule pointing at the service gateway;
    the dev route table now only carries the `0.0.0.0/0` → IGW rule.
  - Removed `oci_bastion_bastion.this` and `oci_bastion_session.managed_ssh`
    (both `count = var.target_instance_ocid != null ? 1 : 0`).
- `terraform/vcn/variables.tf`: removed now-unused vars `bastion_client_cidrs`,
  `target_instance_ocid`, `target_instance_private_ip`,
  `bastion_session_ssh_public_key`.

Per the approved plan and [ansible PR #28](https://github.com/rzkw/ansible/pull/28),
the destroyed bastion and service gateway are NOT reinstated — access is
Tailscale-only. Existing state on the deploy machine is reconciled in Phase B
(tasks 5–7) so `terraform plan` shows no drift for these removals.

Phase A, Task 4 — docs
- `README.md`: expanded the Remote State section with a per-module state-key
  table (`terraform/<module>/terraform.tfstate`) and a warning that a missing
  backend key silently collides with other modules. Removed the Service Gateway
  and Bastion rows from the Deployed Infrastructure table (no longer deployed;
  instance note now says accessed via Tailscale).
- `docs/index.md`: updated the resource table (removed Service Gateway and
  Bastion, noted Tailscale-only access), and the Notes section now documents
  per-module state keys and the no-bastion access model.

## Tasks 1 & 2 completed (PR #60)

Phase A, Task 1 — `AGENTS.md`: plan-approval + references + backend-key policy
- Added a "Plan approval & references" section under Required Workflow: no major
  plans implemented without admin approval; plans require PR review first; every
  plan/report includes a References section (official docs + personal/engineering
  blogs only, never academic papers); plans under `plans/`, reports under
  `reports/` referencing plan/PR/commits.
- Added a Project Structure note: each root module's `backend "oci"` block must
  set a distinct `key` (`terraform/<module>/terraform.tfstate`); a missing key
  defaults to `terraform.tfstate` and silently collides with other modules.

Phase A, Task 2 — restore distinct backend keys
- `terraform/instances/providers.tf`: added `key = "terraform/instances/terraform.tfstate"`
  and `region = "ap-melbourne-1"` to the existing `backend "oci"` block.
- `terraform/vcn/main.tf`: added `key = "terraform/vcn/terraform.tfstate"` and
  `region = "ap-melbourne-1"` to the existing `backend "oci"` block.
- `terraform/budget/providers.tf`: added a `backend "oci"` block with
  `key = "terraform/budget/terraform.tfstate"` and `region = "ap-melbourne-1"`.

Resulting keys: `terraform/vcn/terraform.tfstate`,
